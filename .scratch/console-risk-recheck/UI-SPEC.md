# 重新核对：四种页面状态与文案

状态：首版已实现；配套 [PRD.md](PRD.md)，真实 CTP 只读联调待验收。

## 1. 固定布局

沿用现有控制台的蓝色操作按钮、浅底卡片、环境标签和折叠详情，不另开页面，也不弹出模态对话框。

从上到下固定为：

1. **交易控制台页头**：现有标题及“本机 · 仿真交易”。
2. **当前状态与核对卡片**：标题、状态标签、操作按钮；检查环境和目标合约；简明结论；多仓、空仓、活动委托、未知委托；核对时间和查询连接状态；折叠的检查过程。
3. **上次运行记录**：默认折叠，保留原异常、原轮数、最后审计时间、历史行情、委托、成交及参数；按需继续访问现有详情栏目。
4. **启动下一次运行**：保留原策略选择、预览、参数确认、启动流程。点击成功态“查看启动配置”时展开并移到该区域。

核对卡片显示的是本次查询结果，历史记录显示的是原运行审计。两者分别标注时间和来源，不能用同一组“最新价／活动委托”混在一起。停止状态的主卡片以账户核对为主；历史报价不会占据主指标位置。

宽屏时标题和按钮同排，四项指标同排；窄屏时按钮移到标题下一行，指标变为两列。文案换行，不截断失败原因。颜色始终配合明确状态文字。

| 连接 | 查询连接未建立 |
| 历史摘要 | 上次运行记录 · 异常退出 · 最后记录 09/28 16:17:36 |

旧英文原因码仅放入展开的排障详情。默认可见文案用“上次停止时未取得零持仓确认”，不能写成“上次停止时仍有持仓”。

## 3. 核对中

| 元素 | 固定文案与行为 |
| --- | --- |
| 标题 | 正在核对账户 |
| 状态标签 | 核对中 |
| 主按钮 | 核对中…，禁用 |
| 说明 | 正在查询 IF2610 委托和持仓，尚未形成核对结论。 |
| 进度 | 按真实阶段列出“已完成／进行中／待执行”，不显示虚假的百分比 |
| 耗时 | 已用时 {seconds} 秒 · 查询最长 120 秒；收尾阶段另写“正在关闭查询连接” |
| 指标 | 只展示已完整返回的部分，未返回项为“—”；初查结果标注“待最终复核” |
| 检查过程 | 默认展开，完成后折叠；只报阶段，不滚动输出原始日志 |
| 启动配置 | 核对期间禁用预览、参数编辑/保存和确认启动，显示“账户核对中，请稍候” |

完整阶段为本地检查、连接认证、合约确认、委托初查、持仓查询、委托复核、保存与关闭。真实实现可将快速完成的前三项合并展示，但错误必须能定位到具体阶段。

这期间前端超时不直接宣称查询失败，应继续读取后台任务状态。控制服务暂时不可用时显示“控制服务暂时不可用，核对结果待确认”，不可直接恢复待机。关闭页面不会取消查询；首版不增加“取消核对”按钮。

## 4. 核对成功

| 元素 | 固定文案与行为 |
| --- | --- |
| 标题 | 已停止 · 目标合约核对通过 |
| 状态标签 | 正常待机 |
| 说明 | 截至 {完整核对时间}，IF2610 多空持仓均为 0，无活动或未知委托。 |
| 四项指标 | 多仓 0 手／空仓 0 手／活动委托 0 笔／未知委托 0 笔 |
| 主按钮 | 查看启动配置，仅展开启动区域，不创建确认、不启动交易 |
| 次按钮 | 重新核对 |
| 时间 | 核对时间 {YYYY-MM-DD HH:mm:ss} · 查询快照 |
| 连接 | 查询连接已关闭 |
| 历史摘要 | 上次运行记录 · 原异常已保留 |

主卡片去除“等待风险解除与对账”“最近核对净仓：未核对”和运行中的一键平仓说明。旧异常仍在历史折叠区，不能被改成正常结束。

保留一行范围说明：“本次结果仅覆盖当前配置账户的目标合约；原运行账户一致性未记录。”该说明不需要用户再次确认。

“正常待机”只描述本程序已停止及核对快照，不写“账户实时安全”“交易连接正常”或“可立即下单”。启动区域自行显示“待预览／配置合法／配置待修正／不在策略报价窗口”，与账户核对结论独立。

## 5. 核对失败：区分查到问题与未查清

### 5.1 查到实际风险

- 标题：“核对未通过 · 发现持仓”或“核对未通过 · 发现遗留委托”。
- 标签：“风险待处理”，使用红色。
- 持仓文案：“IF2610 多仓 1 手、空仓 0 手，当前不能恢复正常待机。”
- 委托文案：“IF2610 有活动委托 1 笔、未知状态委托 1 笔，当前不能恢复正常待机。”
- 已完整查询的指标显示实际数字，未查询项显示“—”，不能让未执行的复核显示通过。
- 主按钮：“重新核对”；次按钮：“查看问题详情”，展开该次检查详情。
- 说明：“处理遗留持仓或委托后，可重新核对。此操作不会撤单或平仓。”

多空同时存在时同时展示两个数，不以净仓 0 显示成功；对未知状态委托保留编号和未知原因，但不放置撤单按钮。

### 5.2 查询未完成

- 标题：“核对未完成”。
- 标签：“状态待确认”，使用橙色；保留账户未知提示，不进入绿色成功态。
- 超时文案：“持仓查询超时，当前持仓仍未确认。请在交易前置恢复后重试。”
- 配置缺项文案：“广发仿真配置不完整，尚未发起连接。缺少：{变量名}。”
- 查询出错文案：“{阶段}失败：{脱敏原因}。本次未取得完整核对结果。”
- 保存失败文案：“查询已完成，但结果未能保存；页面恢复未完成，请重试。”
- 主按钮：“重新核对”；次按钮：“查看失败详情”。
- 显示本次尝试时间、失败阶段、已完成检查和待确认项，不以较早成功结果覆盖本次失败。

“核对失败”不新增长期禁止启动的规则。核对任务结束后，启动按钮是否可用仍取决于原有活动状态、预览和配置条件；风险文案继续保留。未预览时原“确认并启动”按钮保持禁用，不能因为点击核对而得到启动许可。

## 6. 跨状态行为

- **重复点击／多窗口**：相同运行只展示同一任务，所有页面统一进度。
- **新运行启动**：新运行界面优先，旧核对结果不能覆盖其状态；核对过程中启动请求返回忙碌。
- **刷新浏览器**：恢复当前后台状态，成功结果不丢失；历史折叠详情不补播告警声音。
- **重启控制服务**：已有成功记录作为历史展示，主标题为“已停止 · 待重新核对”，提示“上次核对通过于 {time}，本次账户配置尚未重新验证”。
- **闭市／缺少行情**：按钮仍可点击；账户查询成功即可恢复待机。行情或报价窗口另标“未验证／等待报价窗口”。
- **多合约**：标题仍为“目标合约核对通过”，范围列出完整合约组；主体逐合约列出四项结果。任何一项未通过时总状态不能成功。
- **可访问性**：状态变化用礼貌播报；真实错误提供明确文本；按钮可键盘操作，禁用原因可见。
