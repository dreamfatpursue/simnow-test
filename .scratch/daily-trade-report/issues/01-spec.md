# 01 — 交易日成交明细 HTML 报告（spec）

**What to build:** 每个交易日一份离线生成的 HTML 成交明细：顶部当日 run 总览与资金汇总，正文按合约列出每轮往返的"挂单时刻/价格/数量 → 成交时刻/价格/数量 → 平仓时刻/价格/数量"及毛盈亏；真实净盈亏与手续费由账户资金差推算，仅在汇总级展示。

**Blocked by:** 无（依赖既有审计目录结构，见 ADR 0004/0005）

**Status:** ready-for-agent

## Problem Statement

策略测试员复盘一天的 SimNow 运行时，成交信息分散在多个审计 run 目录的原始 `events.jsonl` 里，且事件时间戳是单调钟——无法回答"几点挂的单、挂了多久成交、几点平仓"，也看不到每轮盈亏和当天真实盈亏。需要一份按交易聚合、直接可读的成交明细。

## Solution

新增离线命令：扫描审计根目录，按交易所交易日（CTP `TradeDate`，夜盘归入下一交易日）聚合当日全部 run，生成自包含单文件 HTML 到 `reports/trades-YYYYMMDD.html`。审计目录继续是唯一事实源；为使报告可回答时间与盈亏问题，实盘链路最小化补记三类事实：委托/成交回报自带的交易所时间、合约乘数、网关本就轮询的账户资金快照。

## User Stories

1. 作为策略测试员，我想每个交易日得到一份 HTML 成交明细文件，这样收盘后不用翻多个审计目录就能复盘当天全部成交。
2. 作为策略测试员，我想报告只包含有成交合约的逐轮明细，这样页面聚焦在有结果的轮次上。
3. 作为策略测试员，我想每条记录从成交委托的报单时刻开始，这样知道这轮单子挂出多久才成交。
4. 作为策略测试员，我想看到成交委托的挂单价格和数量，这样能核对网格挂单价是否符合 W/D 参数。
5. 作为策略测试员，我想看到成交时刻、成交价格和成交数量，这样能与 SimNow 成交回报逐笔核对。
6. 作为策略测试员，我想看到平仓时刻、平仓价格和平仓数量，这样能核对首成交收口与 FAK 平仓行为。
7. 作为策略测试员，我想每条记录显示开平价差与 tick 点数，这样快速感知每轮的网格利润空间。
8. 作为策略测试员，我想每条记录显示按合约乘数折算的毛盈亏金额，这样不用心算乘数。
9. 作为策略测试员，我想在汇总区看到起始资金、结束资金与真实净盈亏（资金差），这样盈亏是与账户一致的真实数字而非理论值。
10. 作为策略测试员，我想在汇总区看到推算手续费（Σ毛盈亏 − 资金差），这样实时链路拿不到的费用有了可信估计。
11. 作为策略测试员，我想报告页头明确标注毛盈亏未含手续费、净盈亏已含手续费，这样不会误读两套数字。
12. 作为策略测试员，我想夜盘成交自动归入下一个交易日的文件，这样与交易所结算单口径对齐。
13. 作为策略测试员，我想按合约分组浏览当日全部轮次，这样逐合约复盘。
14. 作为策略测试员，我想一轮内多笔平仓成交合并展示（总量、加权均价、首末时刻），这样一行就是一轮完整闭环。
15. 作为策略测试员，我想被撤的挂单尝试不出现在明细里，这样页面不被未成交噪声淹没。
16. 作为策略测试员，我想报告顶部有当日 run 总览（每个 run 每个合约的终态、轮数、失败原因），这样当天的运行画面完整，不会被纯成交视图误导。
17. 作为策略测试员，我想用 `--date 20260815` 生成指定交易日，这样只补我需要的那天。
18. 作为策略测试员，我想不带参数时生成审计中出现的所有交易日，这样一次性补齐历史。
19. 作为策略测试员，我想 `--open` 生成后自动在浏览器打开，这样少敲一条命令。
20. 作为策略测试员，我想补丁之前的历史 run 被明确提示跳过（含计数），这样不会误以为数据丢失或被归错日。
21. 作为策略测试员，我想 HTML 是自包含单文件、无外部依赖，这样拷到别的机器或发给别人都能直接打开。
22. 作为策略测试员，我想实盘链路只补记事实（时间戳、乘数、资金快照）而不改变任何下单决策，这样报告功能不引入新的实盘风险。
23. 作为策略测试员，我想资金快照不含账号等凭证字段，这样审计的凭证安全断言继续成立。
24. 作为开发者，我想让审计目录继续是唯一事实源，这样报告工具崩溃或改版都不影响交易，也不产生第二套数据。
25. 作为开发者，我想报告可随时重新生成，这样修了口径或样式后重跑命令即可，无需重跑策略。

## Implementation Decisions

- **离线生成**（ADR 0004）：独立 CLI 扫描审计根目录聚合成 HTML；不修改 `run_live_grid` 的运行流程。
- **记录粒度**（词汇表"交易日成交明细"）：一条记录 = 一轮往返中成交委托的完整生命周期（报单 → 成交 → 平仓）；同轮被撤委托不展示。
- **交易日口径**：按事件内 CTP 交易日（成交回报日期分量）分组，夜盘自动归入下一交易日；不依赖 run 目录名（目录名是 UTC 时间）。
- **事件扩展**：委托/成交事件增加可选的交易所时间字段，合约事件增加可选的合约乘数字段，均带默认值保持既有构造兼容；时间戳由网关回报自带（报单时间 `InsertDate+InsertTime`、成交时间 `TradeDate+TradeTime`），适配器补传而非自造时钟。
- **资金快照**（ADR 0005）：适配器监听网关既有账户事件并写入 run 级资金快照文件（仅余额/可用/单调时钟时间）；账号属凭证字段禁止落盘；不新增任何 CTP 查询。
- **盈亏口径**：毛盈亏 =（平仓均价 − 开仓价）× 方向 × 数量 × 合约乘数；tick 点数 = 价差 ÷ 最小变动价位；真实净盈亏 = 首个委托前最后一个资金快照与最后平仓终态后第一个资金快照之差；推算手续费 = Σ毛盈亏 − 真实净盈亏。真实净盈亏与手续费只在 run/日汇总级展示，不逐轮归因。
- **开平识别**：沿用现有 client_id 前缀约定（报价 `quote-`、平仓 `flatten-`），不新增字段。
- **轮次重建**：按时间顺序遍历成交事件，开仓成交与其后的平仓成交配对成轮；部分成交按净仓配对。
- **输出**：`reports/trades-YYYYMMDD.html`，纯静态表格单文件，无外部 CSS/JS；结构为页头（交易日、毛盈亏口径声明）→ 当日 run 总览 + 资金汇总 → 按合约分节的逐轮表格。
- **历史数据**：缺交易所时间戳的旧 run 无法归入交易日，跳过并在命令行提示跳过数量。

## Testing Decisions

- 只测外部行为，不测内部函数：报告工具以"审计目录树进 → HTML 文件出"为唯一新接缝，测试用临时目录伪造 `events.jsonl`/`summary.json`/资金快照文件，断言生成 HTML 中的关键行与数值。
- 报告测试必须覆盖：夜盘成交归入下一交易日、同一 run 多轮往返、部分成交配对、多笔 FAK 平仓合并、多合约并发 run、缺时间戳旧 run 被跳过、资金差与推算手续费计算、资金快照含账号字段时审计断言失败。
- 实盘链路改动沿用既有接缝与先例：事件数据类新字段沿用会话测试直接构造事件的写法；适配器时间/乘数传递与资金事件落盘沿用适配器测试的 `SimpleNamespace` 假 vnpy 事件 + 记录型审计桩模式；run 级资金快照文件沿用审计测试的临时目录模式。
- 先例：`tests/test_audit.py`（临时目录断言产物结构与凭证过滤）、`tests/test_ctp_adapter.py`（假事件驱动适配器）、`tests/test_session.py`（直接构造事件测状态机）。

## Out of Scope

- 逐轮资金差归因（每轮真实盈亏/手续费）——已明确拒绝（ADR 0005）。
- 被撤挂单尝试、逐笔委托流水展示。
- 手续费精确值（结算单解析、次日对账）。
- 在线/自动生成报告；`run_live_grid` 结束后的自动触发。
- 图表（K 线、资金曲线）、多日索引页。
- 对下单、收口、平仓等实盘状态机逻辑的任何修改。

## Further Notes

- 成交时间的日期分量即交易所交易日，夜盘会出现"日期超前于自然日"（如自然日 8 月 14 日夜盘成交记入 8 月 17 日交易日），这是口径正确的表现，不是 bug。
- run 目录名为 UTC 命名，本地时区为东八区；报告分组只信任事件内交易所日期，不从目录名推断。
- 网关定时器本就每约 4 秒轮询一次账户资金，首个委托前与最后平仓终态后通常都有可用快照；若边界快照缺失，取最近可用快照并在页面标注。
