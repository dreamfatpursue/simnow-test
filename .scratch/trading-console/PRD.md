# Spec：本机仿真交易控制台

Status: done

## Problem Statement

现有报撤测试可以完成多合约 SimNow 交易、撤单、持仓对账、安全收口和审计，但运行期间主要依赖终端输出、结构化审计文件和交易日志。操作者无法在一个页面中快速判断交易与行情连接是否正常、各合约当前正在等待什么、有哪些活动委托、发生了哪些成交、最近一次确认净仓是什么、安全停止是否真正完成，只能手工翻查日志。

现有 HTML 报告只服务已经写出完整摘要的终态运行，故意拒绝活动运行。它适合事后复盘，不解决运行态势观察和人工结束收口。需要一个仅在本机使用的交易控制台，负责选择并预览现有策略文件、启动唯一交易进程、投影当前运行事实，以及请求既有安全收口。

交易控制台不能拥有 CTP 连接、决定成交、推断持仓、计算盈亏或形成第二套交易状态机。活动运行仍由独立交易进程拥有，审计仍是控制台的唯一事实源。

## Solution

提供一个固定运行在 `http://127.0.0.1:8765` 的本机交易控制台。操作者通过只读方式选择项目根目录中的现有策略文件，选择仿真环境，查看完整规范化参数和策略哈希，完成一次性仿真确认后启动交易进程。

控制台通过同一把活动运行锁保证同一时刻最多存在一个交易进程。发现已有进程时不重复启动，而是提示“已经启动”并切换到该运行。交易进程退出并释放锁后即可启动下一次运行；第一版不保留异常退出待核验状态，也不验证跨运行账户连续性。

活动运行页面每秒从现有审计增量构建运行态势，展示连接、行情、阶段、委托、成交、最后确认持仓、轮次、收口进度和风险。页面关闭或控制服务重启不影响交易进程，重新打开后按运行身份和审计恢复视图。

安全停止通过二次确认向当前活动交易进程发送一次中断请求，复用状态机的人工结束收口。停止意图不可撤回；即使会话已处于 `RISK_HOLD`，也必须记录 `stop_reason=interrupted`，继续保持连接、撤单和对账，确认零活动委托与零净仓后只能结束，不得恢复报价。

## User Stories

1. 作为本机操作者，我希望通过一个固定命令启动交易控制台，从而不需要记忆多组服务参数。
2. 作为本机操作者，我希望控制台启动后自动打开默认浏览器，从而可以立即进入操作页面。
3. 作为本机操作者，我希望终端始终打印控制台地址，从而在浏览器自动打开失败时仍能手工访问。
4. 作为本机操作者，我希望端口被占用时收到明确错误，从而不会误以为控制台已经成功启动。
5. 作为本机操作者，我希望控制台只监听本机回环地址，从而不会意外暴露给局域网或互联网。
6. 作为本机操作者，我希望在空闲页看到项目根目录中的现有策略文件，从而可以选择本次运行使用的配置。
7. 作为本机操作者，我希望控制台只读取符合安全命名规则的策略文件，从而不会读取项目目录之外的内容。
8. 作为本机操作者，我希望控制台只读展示策略而不提供编辑功能，从而继续使用我熟悉的文件编辑方式维护参数。
9. 作为本机操作者，我希望参数不合理时可以在外部修改原始 JSON 后重新预览，从而不需要在控制台维护第二套配置编辑器。
10. 作为本机操作者，我希望无效策略显示现有配置校验错误，从而可以按照与交易入口一致的规则修正文件。
11. 作为本机操作者，我希望明确选择 `first`、`7x24` 或 `guangfa` 仿真环境，从而不会误用上一次运行的环境。
12. 作为本机操作者，我希望只有 `7x24` 环境显示历史行情许可开关，从而不会在不支持的环境中启用该模式。
13. 作为本机操作者，我希望历史行情许可默认关闭，从而避免无意中使用回放行情进行报撤。
14. 作为本机操作者，我希望启用历史行情许可后在选择、预览和运行页面持续看到醒目标记，从而不会忘记当前不是普通实时行情模式。
15. 作为本机操作者，我希望预览完全离线且不建立 CTP 连接，从而查看配置不会产生交易副作用。
16. 作为本机操作者，我希望预览显示规范化后的完整配置和 SHA-256，从而知道交易进程最终会采用什么参数。
17. 作为本机操作者，我希望预览显示所有目标合约、交易所、每侧手数和报价窗口，从而可以在启动前确认交易范围。
18. 作为本机操作者，我希望预览按合约展示全部独立生效参数，包括 W/D/S、轮数上限、安全阈值与 `quote_windows`，不同合约可以使用不同值。
19. 作为本机操作者，我希望高级安全参数可以折叠查看，从而主页面保持清晰，同时所有限制仍可核对。
20. 作为本机操作者，我希望预览只显示缺少的环境变量名称而不显示其值，从而确认环境就绪状态时不泄露凭证。
21. 作为本机操作者，我希望预览完成后获得一次性启动确认，从而启动动作明确对应我刚刚检查的配置和环境。
22. 作为本机操作者，我希望一次性确认没有无意义的时间倒计时，从而配置未变化时不需要重复预览。
23. 作为本机操作者，我希望切换策略、环境或历史行情许可后旧确认立即失效，从而不会启动与预览不一致的运行。
24. 作为本机操作者，我希望原始策略文件在启动前发生变化时系统要求重新预览，从而不会无意执行未确认的参数。
25. 作为本机操作者，我希望一次确认只能启动一次，从而重复点击不会创建第二次运行。
26. 作为本机操作者，我希望控制服务重启后必须重新预览，从而不会沿用已经丢失上下文的确认。
27. 作为本机操作者，我希望控制台直接把原始策略文件交给交易进程，从而不生成额外的临时配置副本。
28. 作为本机操作者，我希望交易进程只在启动时加载一次配置，从而运行期间修改原文件不会热更新活动策略。
29. 作为本机操作者，我希望同一时刻最多只有一个交易进程，从而避免两个运行同时对仿真账户报单。
30. 作为本机操作者，我希望发现交易进程已经启动时得到明确提示并自动进入它的运行页面，从而不会重复启动。
31. 作为本机操作者，我希望交易进程退出后能够直接预览并启动下一次运行，从而不需要额外的跨运行核验步骤。
32. 作为本机操作者，我希望启动请求受理后先看到“正在启动进程”，从而不会把请求受理误认为已经开始交易。
33. 作为本机操作者，我希望合约查询期间看到“正在连接 CTP／查询合约信息”，从而理解 SimNow 等待 2～3 分钟可能是正常现象。
34. 作为本机操作者，我希望初始持仓核对期间看到明确提示，从而知道程序尚未通过零仓启动门槛。
35. 作为本机操作者，我希望稳定行情门槛期间看到“交易运行／等待稳定行情”，从而知道程序已经启动但尚未提交报价。
36. 作为本机操作者，我希望持续有审计事件时系统不因启动检查耗时较长而误判失败，从而可以耐心等待 SimNow 返回结果。
37. 作为本机操作者，我希望总览显示运行 ID、策略哈希、环境和开始时间，从而能够确认正在观察哪一次运行。
38. 作为本机操作者，我希望分别看到交易连接和行情连接状态，从而可以区分两条 CTP 通道的问题。
39. 作为本机操作者，我希望看到每个合约的精确状态和中文阶段，从而既能快速理解，又能保留排障依据。
40. 作为本机操作者，我希望整体阶段按固定优先级汇总，从而多合约处于不同阶段时仍能快速定位最重要状态。
41. 作为本机操作者，我希望 `CLOSING_WAIT` 显示为仍在交易运行，从而知道对侧委托仍可能成交。
42. 作为本机操作者，我希望只有撤单、持仓对账和 FAK 平仓显示为安全收口，从而不会误解当前风险程度。
43. 作为本机操作者，我希望看到每个合约的最新 Last、Bid1、Ask1 和行情时间，从而判断报价依据是否新鲜。
44. 作为本机操作者，我希望行情过期阈值按每个合约自己的配置计算，从而不同合约使用正确的新鲜度标准。
45. 作为本机操作者，我希望看到当前报价窗口及结束时间，从而理解会话为何报价、暂停或开始收口。
46. 作为本机操作者，我希望看到当前轮次和最大轮次，从而了解本次测试的进度。
47. 作为本机操作者，我希望看到待受理和未终态逻辑委托数量，从而掌握当前仍可能产生交易结果的委托。
48. 作为本机操作者，我希望展开逻辑委托查看方向、开平、类型、价格、数量、成交量和状态路径，从而理解委托生命周期。
49. 作为本机操作者，我希望成交按交易所成交 ID 去重展示，从而不会把重复回报误认为新成交。
50. 作为本机操作者，我希望最近成交显示方向、开平、价格、数量和交易所时间，从而快速了解最新真实成交。
51. 作为本机操作者，我希望持仓明确标为最近一次查询确认的净仓和时间，从而不会把成交累加结果误认为 CTP 持仓事实。
52. 作为本机操作者，我希望查看结构化因果时间线，从而理解稳定行情、报价、撤换、成交、对账、FAK 和终止之间的关系。
53. 作为本机操作者，我希望页面不根据行情穿价推断成交，从而所有成交结论都来自 CTP 权威回报。
54. 作为本机操作者，我希望页面不重新运行历史状态机或猜测旧事件原因，从而展示结果忠实于当时审计事实。
55. 作为本机操作者，我希望活动页面不显示毛盈亏、净盈亏、浮动盈亏或手续费估算，从而专注运行安全而不混淆事后经济分析。
56. 作为本机操作者，我希望点击安全停止前看到二次确认，从而明确该操作会停止全部合约并开始安全收口。
57. 作为本机操作者，我希望重复提交安全停止不会重复触发不同收口动作，从而停止请求具备幂等行为。
58. 作为本机操作者，我希望页面数据过期时仍可请求安全停止，从而页面越不清晰时仍能尝试结束活动运行。
59. 作为本机操作者，我希望安全停止只作用于活动锁和运行身份都匹配的交易进程，从而不会误伤无关进程。
60. 作为本机操作者，我希望停止后看到每个合约的撤单、对账和 FAK 阶段，从而知道收口仍在进行而不是已经完成。
61. 作为本机操作者，我希望停止意图不可撤回，从而收口期间不会重新开始报价。
62. 作为本机操作者，我希望处于 `RISK_HOLD` 的合约收到停止后仍记录停止意图，从而连接恢复并确认安全后不会继续挂单。
63. 作为本机操作者，我希望 `RISK_HOLD` 在风险未解除时保持连接、持续撤单和对账，从而尽可能获得安全终态证明。
64. 作为本机操作者，我希望只有全部合约终态、零活动委托和零净仓时才显示安全停止完成，从而按钮受理不会被误当作 CTP 执行成功。
65. 作为本机操作者，我希望控制台不提供强制完成或强制退出，从而不会绕过委托和持仓安全证明。
66. 作为本机操作者，我希望 `FAILED` 明确表示零活动委托、零净仓的安全失败终态，从而不会把失败原因与账户未知风险混为一谈。
67. 作为本机操作者，我希望交易进程异常退出单独显示并保留每个合约的最后精确状态，从而不会伪造 `FAILED` 终态。
68. 作为本机操作者，我希望异常退出只显示最后已知事实而不冒充当前账户状态，从而清楚知道信息的时效边界。
69. 作为本机操作者，我希望异常退出释放活动锁后仍可启动下一次运行，从而符合本机单人联调的简化准入规则。
70. 作为本机操作者，我希望普通安全失败不触发不可关闭的红色风险横幅，从而关键风险提醒保持可信。
71. 作为本机操作者，我希望残仓、未知委托、超时、连接中断和 `RISK_HOLD` 显示固定红色横幅，从而关键风险始终醒目。
72. 作为本机操作者，我希望页面打开期间每个新的合约风险原因只响一次，从而及时得到提醒而不被持续状态更新打扰。
73. 作为本机操作者，我希望风险解除后再次发生时重新响一次，从而能够识别新的风险轮次。
74. 作为本机操作者，我希望刷新页面时既有风险只恢复横幅而不补播声音，从而刷新不会制造虚假的新告警。
75. 作为本机操作者，我希望浏览器阻止声音时仍能依赖红色横幅，从而声音能力不会影响安全展示。
76. 作为本机操作者，我希望页面数据中断时冻结最后数值并显示最后更新时间，从而不会把旧数据误认为实时数据。
77. 作为本机操作者，我希望关闭或刷新浏览器不会发送停止请求，从而浏览器生命周期不会控制交易生命周期。
78. 作为本机操作者，我希望控制服务退出时交易进程继续运行，从而界面故障不会中断 CTP 收口或交易会话。
79. 作为本机操作者，我希望控制服务重启后恢复同一运行的页面投影，从而不需要重新启动交易进程。
80. 作为本机操作者，我希望页面和接口永远不返回账号、密码、鉴权码或前置地址，从而 CTP 凭证仍只存在于环境配置中。
81. 作为本机操作者，我希望控制台拒绝非本机 Host、Origin 和跨域状态变更，从而其他网页不能通过 localhost 触发启动或停止。
82. 作为本机操作者，我希望状态变更请求要求当前控制服务会话令牌，从而旧页面或跨站请求不能复用控制权限。
83. 作为维护者，我希望控制台使用现有配置加载器、状态机和审计格式，从而不维护重复业务规则。
84. 作为维护者，我希望页面只消费结构化审计而不解析终端文本，从而展示不依赖易变化的人类日志文案。
85. 作为维护者，我希望控制台使用标准库和静态页面实现，从而不引入 Web 框架、Node 构建链、数据库或消息系统。
86. 作为维护者，我希望投影增量读取审计并忽略未写完的尾行，从而活动写入期间不会误判审计损坏。
87. 作为维护者，我希望投影按逻辑委托和成交身份去重并限制内存中的历史数量，从而长时间运行不会无限增长页面状态。
88. 作为维护者，我希望现有终态报告保持不变，从而运行中控制台不会破坏既有复盘工具。

## Implementation Decisions

- 变更面限定为：新增本机控制服务与静态页面、新增共享活动锁与无凭证运行身份模块、修改现有交易入口接入同一把锁并补充异常退出摘要、修改确定性会话状态机修复 `RISK_HOLD` 中断语义；现有配置加载、审计格式与终态报告尽量复用。
- 新增一个本机控制服务入口和一个无构建步骤的静态 HTML/CSS/JavaScript 页面。固定命令为 `python run_trading_console.py`。
- HTTP 服务固定监听 `127.0.0.1:8765`，不提供 host 或 port 参数。启动后使用 Python 标准库尝试打开默认浏览器，并始终在终端打印访问地址。端口占用时明确报错退出，不自动选择其他端口。
- 控制台与交易进程分离。控制服务只负责策略文件选择、预览确认、单活动运行准入、进程启动、审计投影和安全停止请求；独立交易进程继续拥有 CTP、状态机、报撤、收口和审计。
- 浏览器和控制服务都不是交易进程的生命周期所有者。交易进程独立于控制服务进程组运行；页面关闭、刷新或控制服务重启均不结束交易进程。
- 第一版使用 Python 标准库 HTTP 服务和 JSON，不引入后端 Web 框架、数据库、Node 构建链、WebSocket、SSE、图表库、消息队列或第二份实时状态存储。
- 控制台只列出项目根目录中的 `strategy*.json`。所选名称必须是安全 basename，并拒绝路径穿越和符号链接越界。
- 控制台不提供策略编辑、创建、覆盖或另存功能。操作者在外部修改原始 JSON 后重新预览。
- 预览复用现有多合约配置加载器，完成读取、凭证字段拒绝、规范化、字段校验和 SHA-256 计算。页面不复制配置校验逻辑。
- 配置字段归属固定如下：

  | 归属 | 字段 |
  | --- | --- |
  | 运行根节点 | `version: 2`、`contracts` 合约列表 |
  | 每个合约独立 | `symbol`、`exchange`、`target_lots`、`w_ticks`、`d_ticks`、`s_ticks`、`book_protection_multiple`、`reanchor_confirmation_seconds`、`stable_market_seconds`、`action_limit_per_minute`、`cancel_timeout_seconds`、`flatten_timeout_seconds`、`flatten_adverse_ticks`、`max_round_trips`、`closing_wait_seconds`、`quote_ack_timeout_seconds`、`max_tick_age_seconds`、`quote_windows` |

- 顶层策略参数一律拒绝并提示移入合约项，不保留全局值加局部覆盖的优先级；可选默认值逐合约独立填充。现有文件迁移保留原生效数值，历史审计不改写，仅展示/报告兼容旧根节点公共参数。

- 预览不连接 CTP，也不产生审计目录。环境检查只返回就绪状态或缺少的变量名，不返回任何值。
- 环境必须显式选择 `first`、`7x24` 或 `guangfa`。历史行情许可只允许 `7x24`，默认关闭；启用后在选择、预览和运行页面持续展示 `replay_override`。
- 成功预览产生一次性确认身份，绑定策略文件安全名称、环境、市场数据模式和预览哈希。确认只存在于控制服务内存中，没有时间期限；切换选择、源文件哈希变化、启动消费或控制服务重启都会使其失效。
- 启动时控制服务重新读取原始策略文件并比较哈希。哈希不一致时拒绝并要求重新预览；一致时将同一原始文件路径交给现有交易入口。
- 不创建临时策略快照，也不把整段 JSON 放入进程命令行。交易进程启动时只加载一次原始文件，后续文件修改不改变本次运行。接受控制服务复核与子进程读取之间仍可能发生本机手工修改的极短窗口。
- 所有已确认的交易启动路径，包括页面启动和命令行直接启动，都必须获得同一把 POSIX 活动运行锁；预览不占锁。
- 活动锁由交易进程持有到进程实际退出。启动发现锁已占用时返回已有运行身份并切换页面，不启动第二个进程；锁空闲时允许启动新进程。
- 活动锁是下一运行的唯一进程级准入条件。进程退出后不保留待核验状态，不要求只读 CTP 核验，也不验证前后运行是否使用同一账户。新运行仍保留现有目标合约零仓启动门槛。
- 无凭证运行身份记录 run ID、PID、开始时间、环境、市场数据模式、策略哈希、合约集合和审计目录。不得仅凭 PID 判断活动进程；停止和重新接管必须结合活动锁与运行身份。
- 交易进程的 stdout/stderr 写入仅当前用户可读的本地运行日志，不通过页面提供，也不作为连接、成交或安全完成的事实源。
- 页面每秒获取一次当前投影。控制服务按文件偏移增量读取每合约审计，忽略未写完的 JSONL 尾行；重启后流式重建当前运行，不一次性加载全部 Tick。
- 投影按 `client_id` 聚合逻辑委托、按 `trade_id` 去重成交，只保留当前状态和有限数量的关键因果事件。完整审计继续保留全部原始事实。
- 运行态势只来自结构化连接、合约、行情、动作、委托、成交、持仓查询完成、状态变化、因果轨迹和终态摘要。不得解析终端自然语言，不得根据行情穿价推断成交，不得用成交累加值冒充持仓查询结果。
- 复用现有报告中的原因代码中文标签和委托、成交字段口径，但活动运行不调用要求终态摘要的报告生成流程。
- 本地 HTTP 接口固定为：

  | Method | Path | Purpose |
  | --- | --- | --- |
  | `GET` | `/api/strategies` | 列出安全范围内的策略文件及校验状态 |
  | `POST` | `/api/preview` | 读取并规范化所选原始策略，返回完整预览、哈希和一次性确认身份 |
  | `POST` | `/api/run/start` | 消费确认身份，检查活动锁并启动或返回已有运行 |
  | `GET` | `/api/run/current` | 返回空闲、启动中、活动、收口、风险或终态投影 |
  | `POST` | `/api/run/stop` | 幂等请求当前活动运行安全停止 |

- 启动展示不新增交易状态。启动请求已受理但进程尚未持锁时显示“正在启动进程”；`WAITING_FOR_CONTRACT` 显示“正在连接 CTP／查询合约信息，SimNow 等待 2～3 分钟属正常”；`WAITING_FOR_ZERO_POSITION` 显示“合约已就绪／正在核对初始持仓”；`WAITING_FOR_STABLE_QUOTE` 显示“交易运行／等待稳定行情”。
- 只要交易进程持有活动锁且审计事件持续到达，就不因启动检查耗时较长而判定失败。进程退出、启动异常或明确失败事件才结束启动流程。
- 每个合约展示精确 `SessionState` 及中文阶段。整体阶段采用固定优先级和归属：

  | 整体阶段 | 精确状态 |
  | --- | --- |
  | 风险 | `RISK_HOLD` |
  | 安全收口 | `CLOSING_CANCELS`、`CLOSING_RECONCILE`、`FLATTENING` |
  | 交易运行 | `WAITING_FOR_STABLE_QUOTE`、`PAUSED`、`QUOTE_PENDING`、`QUOTING`、`REPLACING`、`CLOSING_WAIT` |
  | 启动准备 | `WAITING_FOR_CONTRACT`、`WAITING_FOR_ZERO_POSITION` |
  | 终态 | 所有合约均为 `FINISHED` 或 `FAILED` |

- 多合约混合状态按“风险 > 安全收口 > 交易运行 > 启动准备 > 终态”汇总。已经终态的合约不覆盖仍在运行的合约。`PREVIEW` 是运行前页面状态；进程异常退出是运行级控制状态，二者都不伪装成合约阶段。
- 合约详情展示运行参数、逻辑委托生命周期、去重成交和结构化因果时间线。Tick 与 Clock 的无动作事件不进入关键时间线，原始 JSON 默认隐藏。
- 安全停止需要二次确认，作用于整次运行而不是单个合约。控制服务校验活动锁和运行身份后向交易进程发送一次 `SIGINT`；重复请求返回同一收口状态。
- CLI 第一次 KeyboardInterrupt 和页面安全停止进入同一条 `InterruptEvent` 收口链路。每个非终态会话都必须先记录不可撤回的 `stop_reason=interrupted`，包括已经处于 `RISK_HOLD` 的会话。
- 已记录停止意图的 `RISK_HOLD` 保持 CTP 连接，继续撤销可识别委托和查询持仓；只有活动委托为零且最终净仓为零后才能进入 `FINISHED`，不得返回 `WAITING_FOR_STABLE_QUOTE` 或再次报价。
- 页面在停止请求后显示“收口中”，持续展示逐合约撤单、对账和 FAK 阶段。只有所有合约达到安全终态、活动委托为零、最终净仓为零并关闭连接后，才显示安全停止完成。
- 不提供撤回停止、强制完成、强制退出、单合约停止、手工撤单或手工平仓控制。
- `SessionState.FAILED` 专指已经确认零活动委托、零净仓的安全失败终态，本身不触发关键风险横幅。
- 交易进程在会话未到安全终态前退出时，使用独立的运行级“进程异常退出”状态，保留每个合约最后精确状态和最后已知事实，不再以合成 `FAILED` 覆盖会话。
- 进程异常退出后活动锁释放，允许下一次运行。页面可以显示上一运行最后已知风险，但不得把它冒充为当前账户事实；控制台不核验或处置遗留委托和仓位。
- 页面请求失败，或活动运行连续三秒没有新的 Clock/Event 审计事实时，冻结最后快照并显示数据已中断及最后更新时间。
- 投影过期时禁用依赖当前投影的预览和启动，但只要控制服务可访问、活动锁仍被持有且运行身份匹配，安全停止保持可用。服务端不得以行情或审计投影不新鲜为由拒绝停止。
- `RISK_HOLD`、残仓、未知委托、撤单超时、FAK 超时、活动运行连接中断和未到安全终态的进程异常退出显示不可关闭的红色横幅。安全失败终态 `FAILED` 不显示关键风险横幅。
- 页面打开期间，每个新的“run ID＋合约＋风险原因”首次出现时播放一次短提示音；同一风险持续更新不重复，解除后重新出现时再次播放。打开或刷新页面时，既有风险只恢复横幅，不补播声音。声音是尽力而为的辅助提醒。
- Host 只接受 `127.0.0.1:8765` 和 `localhost:8765`；状态变更请求的 Origin 只接受 `http://127.0.0.1:8765` 和 `http://localhost:8765`。其他 Host、Origin、端口、IPv6 地址和非回环来源全部拒绝。
- 页面与接口同源，不启用 CORS。状态变更请求必须是 JSON，并携带当前控制服务随机会话令牌。页面按钮禁用不是安全边界，所有约束由服务端再次校验。
- 页面、接口、运行身份、运行日志和审计不得返回或保存 CTP 账号、密码、经纪商代码、鉴权码、产品信息或前置地址。

## Testing Decisions

- 好测试只验证外部可观察行为和安全不变量，不断言私有字段布局、内部函数调用次数、具体线程实现或像素级样式。
- 控制服务 API 是主要高层测试接缝。使用临时项目目录、合成策略、合成审计和可控交易进程替身，覆盖策略枚举、预览、确认、启动、发现已有运行、当前投影和安全停止的完整闭环。
- 多合约配置加载器是配置测试接缝。复用现有配置测试方式，验证控制台预览与交易入口得到相同的 effective 配置和 SHA-256，凭证字段及越界文件仍被拒绝。
- 活动运行锁在交易入口层测试，因为命令行和控制台都必须经过同一入口。验证并发启动最多一个成功、锁占用时返回已有运行、进程退出后锁释放以及预览不占锁。
- 状态机保留一个聚焦安全测试接缝。构造已经处于 `RISK_HOLD` 的会话，发送 `InterruptEvent`，验证停止意图被保留；随后模拟零活动委托和零净仓恢复，验证只能进入 `FINISHED` 且不会再产生报价动作。
- 复用现有状态机测试先例，验证 CLI 中断在正常报价、收口和 `RISK_HOLD` 三类阶段都遵守同一停止语义。
- 交易入口异常测试验证未终态会话不会再被合成 `FAILED` 覆盖；`FAILED` 只在零活动委托和零净仓时作为安全失败终态输出。
- 审计投影测试使用合成 JSONL，从最高层投影结果验证连接、行情、精确状态、中文阶段、五档整体阶段、轮次、活动委托、成交、最后确认持仓、风险和因果时间线。
- 投影测试覆盖重复 `TradeEvent` 按成交 ID 去重、重复 `OrderEvent` 仍归属同一逻辑委托、无动作 Tick/Clock 不进入关键时间线，以及未写完尾行不污染最后正确快照。
- 多合约阶段测试覆盖混合状态的固定优先级，尤其验证 `CLOSING_WAIT`、`PAUSED`、`WAITING_FOR_STABLE_QUOTE` 属于交易运行，`FAILED` 不覆盖仍在运行的合约。
- 启动投影测试分别覆盖请求受理、进程持锁、合约查询、初始持仓核对和稳定行情等待，并验证持续有审计事件时不会因 2～3 分钟等待文案而自动失败。
- 确认测试覆盖一次性消费、无时间过期、服务重启失效、策略选择变化、环境变化、历史行情许可变化和启动前源文件哈希变化。
- HTTP 边界测试覆盖固定监听地址、端口占用、允许与拒绝的 Host/Origin、非 JSON 状态变更、缺少或错误会话令牌、路径穿越和符号链接越界。
- 数据过期测试覆盖快照冻结、最后更新时间、预览/启动禁用，以及活动锁与运行身份仍匹配时安全停止继续可用。
- 停止接口测试覆盖二次确认后的幂等结果、运行身份不匹配时拒绝、活动锁释放后拒绝，以及页面不提前显示安全停止完成。
- 控制服务重启测试验证交易进程 PID 不变、活动锁继续被交易进程持有，并能从运行身份和已有审计恢复同一 run ID 的当前投影。
- 进程异常退出测试使用交易进程替身，验证页面保留最后精确状态和最后已知风险、活动锁释放、下一次预览和启动可用，并且没有只读核验流程。
- 风险提醒使用合成投影进行页面行为测试：同一风险持续只响一次、解除后重入再次响、刷新时既有风险不补响、浏览器拒绝声音不影响横幅。
- 手工界面验收覆盖默认浏览器打开、桌面布局、键盘操作、策略校验错误、确认弹窗、连接与启动文案、红色风险横幅、提示音和页面刷新恢复。
- 真实 SimNow 验收沿用现有分阶段安全规则：先做受控无成交运行，再检查连接、行情、双边委托和页面投影，最后二次确认安全停止并观察逐合约撤单、对账和必要的 FAK。只有审计证明零活动委托、零净仓和安全终态才判定通过。
- 真实 SimNow 环境不主动执行进程崩溃故障注入；异常退出流程只用测试替身验证。
- 发布前运行全部现有离线单元测试和语法检查。测试通过只证明离线行为，不替代真实 SimNow 的连接、回报时序和人工安全验收。
- 现有测试先例包括配置规范化与拒绝规则、确定性状态机事件驱动测试、交易入口摘要测试、审计写入测试和离线报告投影测试；新增测试沿用这些模式，不创建第二套测试框架。

## Out of Scope

- 生产环境、实盘前置和真实资金交易授权。
- 局域网、互联网、远程访问、多用户、登录系统、角色权限和任务调度。
- 多个同时活动的运行、跨运行资金分配和账户级组合风险控制。
- 异常退出后的待核验状态、只读账户核验、账户连续性验证和跨运行安全锁定。
- 自动接管或处置异常退出前遗留的活动委托和仓位。
- 在控制台中编辑、创建、覆盖或另存策略文件。
- 为确认后的配置创建临时快照、通过命令行传递整段 JSON，或进行活动运行参数热更新。
- 手工下单、改单、单笔撤单、单合约停止、手工平仓、强制退出和强制完成。
- 运行中毛盈亏、净盈亏、浮动盈亏、手续费估算、净值曲线和账户经济分析。
- K 线、价格曲线、盘口深度图和移动端布局。
- 历史运行列表、历史运行检索和在控制台中重新生成终态报告。
- 替代、重写或弱化现有终态 HTML 报告。
- 页面原始日志滚屏、stdout/stderr 展示和终端自然语言解析。
- 根据行情穿价推断成交、根据成交累加推断持仓，或重新运行状态机解释旧审计。
- 本机系统通知、短信、邮件、聊天软件通知和任何外部告警渠道。
- 数据库、Web 框架、Node 工具链、WebSocket、SSE、消息队列、图表依赖和第二份 live-state 存储。
- Host、端口、网络监听地址和远程访问方式的运行时配置。

## Further Notes

- 本 Spec 使用项目领域词汇中的“策略文件预览”“交易启动确认”“活动运行”“单活动运行准入”“安全失败终态”“进程异常退出”“运行态势”“运行阶段”和“人工结束收口”。
- 架构遵循现有决策：浏览器视图不拥有交易生命周期；控制服务不承载交易进程；活动进程锁是下一运行的唯一准入条件。
- 审计是运行态势的唯一事实源，控制台只是投影。CTP 回报和状态机继续拥有委托、成交、持仓和安全终态语义。
- 第一版主动接受两个本机简化边界：控制服务复核配置与子进程读取原始文件之间存在极短手工修改窗口；进程异常退出后不会核验旧账户或阻止下一运行。
- `FAILED` 与进程异常退出必须保持不同含义。前者是状态机已证明安全的失败终态，后者只是进程生命周期事实和最后已知风险。
- 页面数据过期与安全停止资格彼此独立。投影不新鲜时应加重警告，但只要仍能确认活动进程，就不应阻止人工结束收口。
- 当前状态为 `ready-for-agent`。实现完成前，现有交易代码、策略文件和 CTP 运行行为保持不变。
