# 09 — 收口撤单超时与关联查仓

**What to build:** 系统最多等待十秒确认收口阶段委托进入终态；无论发生迟到成交还是撤单超时，都会发起新的、带关联号的目标合约持仓查询，并只接受匹配本次查询的完成事件，平仓数量以实际净仓为准。

**Blocked by:** 07 — 首次成交触发单次成交收口；08 — 人工中断复用收口路径

**Status:** ready-for-agent

- [ ] 收口阶段对剩余测试委托等待终态不超过配置的十秒上限，超时会被记录为失败风险而不是无限等待。
- [ ] 撤单等待期间到达的迟到成交会更新实际净仓，并不会恢复报价。
- [ ] 撤单终态完成或超时后都会发起新的目标合约持仓查询，并保存该查询的关联号。
- [ ] 非本次收口查询关联号的持仓完成事件不能授权平仓或结束收口；匹配事件才可推进流程。
- [ ] 后续平仓数量取关联查询确认的最终净仓，而不是目标委托手数或预期成交量。
