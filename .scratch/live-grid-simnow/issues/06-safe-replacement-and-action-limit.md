# 06 — 安全替换、订单终态与报撤限流

**What to build:** 重定锚或替换报价时，系统先撤销旧委托，等待所有旧委托收到 CTP 终态回报后才提交新报价；普通报撤动作遵守滚动一分钟限额，必要安全撤单始终尝试，订单生命周期只由 CTP 回报决定。

**Blocked by:** 05 — 行情重定锚与恢复确认

**Status:** ready-for-agent

- [ ] 旧测试委托处于已提交或已请求撤单但尚未收到终态时，替换流程不会提交新的报价。
- [ ] 只有全部待替换旧委托收到终态 CTP 回报后，才允许提交新的报价对。
- [ ] 委托回报和成交回报分别更新订单生命周期与实际成交量；延迟或缺失确认只产生安全等待或审计告警，不会制造重复报价。
- [ ] 普通报价提交和撤单请求遵守每滚动一分钟 60 次的动作限额，达到限额后暂停普通报价。
- [ ] 必要的安全撤单即使普通动作限额已满也会尝试，并在动作记录中可见。
