## 对正常挂单的隔离证据与性能边界

离线基准三轮交替比较：关闭录制、正常录制、注入 500ms 分片写入延迟。每组 6078 次事件处理，使用真实 AuditWriter 写盘/flush 与假报撤接口，涵盖报价、委托确认、模拟成交、FAK、撤余单、持仓对账和停止。9 组动作与状态指纹完全一致。

| 模式 | 三轮 P99 范围 |
| --- | --- |
| 无录制 | 0.0363–0.0526 ms |
| 正常录制 | 0.0538–0.0684 ms |
| 慢盘录制 | 0.0657–0.0724 ms |

相对同轮基线的最大 P99 增量约 0.0361 ms，小于预设的 max(1ms, 基线 5%) 门槛。慢盘故障组的录制进程按预设 3 秒停止预算报告 writer_stop_timeout 和 460–480 条未落盘，策略动作没有改变；这是故障注入的预期结果，不是采集成功。正常录制组均无丢弃或未落盘。

最大单次样本存在主机调度抖动：基线出现约 7.46ms，正常录制最大约 0.566ms，慢盘最大约 0.542ms。不能据此推断录制改善性能，更不能宣称绝对零影响。

该基准只覆盖 adapter._consume 起点到假动作派发，不覆盖真实网络、原生回调或事件队列等待。四次实测均为只读 MD，不验证真实挂单、成交延迟或活跃 TD 会话并行行为。跨日/夜盘长时采集、真实断网恢复、断电持久性、其他环境及主机容量上限仍未验收。

完整基准结果见 `benchmark-results.json`；可通过 `tests/benchmark_market_recorder.py` 复跑。使用步骤和故障判断见 `docs/market-data-recorder.md`。
