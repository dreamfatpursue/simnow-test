# 01 — 单 run 委托成交因果 HTML 报告（spec）

**What to build:** 为每个具有新格式审计因果轨迹且已完整收尾的 SimNow run 手动生成一份自包含 HTML：展示运行参数、审计品种身份、运行因果时间线、全部逻辑委托、关联成交、逐笔可展开的决策原因与计算过程，以及既有可靠盈亏口径。

**Blocked by:** 无（遵循 ADR 0004、0005、0007）

**Status:** ready-for-agent

## Problem Statement

SimNow 操作者主动复盘一次运行时，只能面对按合约拆分的原始事件日志。现有交易日报告聚焦发生过成交的轮次，明确排除了大量未成交后撤销的报价，因此无法回答“这一笔单为什么挂在这个价格、为什么被撤、之后替换成了哪一笔、整个会话为什么进入下一个状态”。当前日志虽然保存了触发事件、前后状态和动作，却在状态机到审计写入边界丢失了锚点、判定原因和计算中间值；让报告器事后重放状态机，会使历史解释依赖当前代码版本并可能产生错误结论。

操作者需要在想看结果时手动指定一个完整 run，得到一份直接可读、可追溯且不接触实时下单链路的 HTML。报告必须以运行时已经落盘的结构化审计事实为准，完整展示未成交、撤销、拒单、成交和平仓委托，同时清楚解释每个有意义的状态变化和动作。

## Solution

状态机在处理事件时同步产出审计因果轨迹：用稳定原因代码记录受影响的逻辑委托、当时行情、锚点、策略参数、计算操作数、判定结果和动作结果。审计写入边界把该轨迹与既有事件、动作及前后状态一起落盘，并显式标记新审计格式版本。无动作的行情和时钟事件继续作为原始事实保留，但不增加解释噪音。

现有报告命令增加单 run 模式。操作者手动传入 run 审计目录，命令先验证审计格式、run 摘要和终态完整性，再生成一份自包含 HTML 到报告目录，可选生成后打开。报告按合约分区，提供运行因果时间线和按实际提交顺序排列的完整逻辑委托表；每笔逻辑委托一行，通过可展开详情展示其创建、状态变化、撤单或替换原因、计算过程和关联成交。报告只翻译结构化轨迹，不重放状态机、不补中文品种映射、不推导旧日志。

## User Stories

1. As a SimNow 操作者, I want 在需要复盘时手动指定一个审计 run 生成 HTML, so that 报告生成与实时挂单完全解耦。
2. As a SimNow 操作者, I want 一份报告只对应一个完整 run, so that 参数、委托、成交和终态不会与其他运行混在一起。
3. As a SimNow 操作者, I want 一份报告覆盖该 run 中的全部目标合约, so that 多合约运行不需要逐个执行命令。
4. As a SimNow 操作者, I want 看到品种代码、准确合约、交易所、合约乘数和最小变动价位, so that 我能确认报告对应的真实交易对象。
5. As a SimNow 操作者, I want 品种身份只来自当次审计事实, so that 当前合约信息或人工映射不会改写历史。
6. As a SimNow 操作者, I want 看到本次运行的完整生效策略和策略哈希, so that 我能确认当时实际使用的参数而不是当前配置文件。
7. As a SimNow 操作者, I want 运行参数与实际委托参数分区展示, so that W、D、S 等策略设置不会与价格、方向和手数混淆。
8. As a SimNow 操作者, I want 报告包含全部逻辑委托, so that 未成交、撤销和拒单的报价不会被成交视图过滤掉。
9. As a SimNow 操作者, I want 同一委托的重复 CTP 状态回报被合并为一笔逻辑委托, so that 回调次数不会被误算成挂单次数。
10. As a SimNow 操作者, I want 每笔逻辑委托展示 client identity、用途、方向、开平、订单类型、限价和数量, so that 我能逐项核对实际发送的请求。
11. As a SimNow 操作者, I want 每笔逻辑委托展示去重后的状态路径和最终结果, so that 我能快速区分未成交撤单、拒单、部分成交和全部成交。
12. As a SimNow 操作者, I want 委托按实际提交时间排列, so that 我能顺序阅读撤旧单与挂新单的完整过程。
13. As a SimNow 操作者, I want 买卖报价与 FAK 平仓委托处于同一时间线, so that 开仓、撤单和收口不会被拆成互不相干的表格。
14. As a SimNow 操作者, I want 每笔委托提供默认收起的“查看详情”, so that 主表保持可扫描，同时需要时能深入检查。
15. As a SimNow 操作者, I want 首次报价详情展示当时行情、锚点和最小变动价位, so that 我能知道价格计算的输入来自哪里。
16. As a SimNow 操作者, I want 首次报价详情展示 W、D、距离 tick 数和买卖价格计算结果, so that 我能逐步核对报价公式。
17. As a SimNow 操作者, I want 盘口保护撤单详情展示买一、卖一、价差 tick 数、保护倍数和严格比较结果, so that 我能确认撤单是盘口过宽而不是价格移动。
18. As a SimNow 操作者, I want 重定锚详情展示旧锚点、当前价格、新锚点、W、S 和越界确认时长, so that 我能确认锚点为何以及如何移动。
19. As a SimNow 操作者, I want 撤单详情明确记录稳定原因代码而不是事后猜测, so that `market_pause` 与 `reanchor` 不会被混淆。
20. As a SimNow 操作者, I want 被撤委托与后续替代委托相互引用, so that 我可以沿着旧报价追到新报价。
21. As a SimNow 操作者, I want 同一组买卖报价共享替换上下文但仍各自保留逻辑委托行, so that 双边关系与逐笔事实同时清楚。
22. As a SimNow 操作者, I want 委托详情展示 CTP 接受时间、交易所委托号和终态时间, so that 我能核对请求到交易所回报的生命周期。
23. As a SimNow 操作者, I want 成交委托关联成交编号、成交时间、价格、方向和数量, so that 我能与 SimNow 成交回报逐笔核对。
24. As a SimNow 操作者, I want 部分成交和多笔成交分别保留并汇总成交量, so that 合并展示不会丢失原始成交事实。
25. As a SimNow 操作者, I want 首次成交详情说明为何进入价差窗口, so that 状态转换与具体成交直接关联。
26. As a SimNow 操作者, I want 价差窗口详情展示配置时长、开始时间和结束原因, so that 我能区分对侧成交与窗口超时。
27. As a SimNow 操作者, I want 对侧在窗口内成交时看到“价差完成”路径, so that 我能确认本轮为何不发送 FAK 平仓。
28. As a SimNow 操作者, I want 窗口超时时看到当时净仓和 FAK 方向, so that 我能确认平仓动作与敞口一致。
29. As a SimNow 操作者, I want FAK 详情展示买一卖一、初始可执行价、不利 tick 上限和最终委托价, so that 我能核对受限追价没有突破安全边界。
30. As a SimNow 操作者, I want 平仓成交后看到为何撤销剩余对侧委托, so that 收口顺序可以从报告直接验证。
31. As a SimNow 操作者, I want 看到关联查仓请求及其净仓结果, so that 一轮结束是由 CTP 持仓事实确认而不是行情推断。
32. As a SimNow 操作者, I want 每个合约有独立的运行因果时间线, so that 无法归属单笔委托的会话变化仍然可见。
33. As a SimNow 操作者, I want 运行时间线展示收到合约元数据和启动查仓, so that 首次报价前的安全门槛完整可查。
34. As a SimNow 操作者, I want 运行时间线展示零仓确认和稳定行情资格, so that 我能确认系统不是连接后立即下单。
35. As a SimNow 操作者, I want 运行时间线展示每轮对账归零和重新进入行情资格, so that 连续报价的轮次边界清楚。
36. As a SimNow 操作者, I want 运行时间线展示达到轮数上限、收盘、中断或失败的明确原因, so that 终态不只是一个枚举值。
37. As a SimNow 操作者, I want 延迟成交、撤单超时、平仓拒单和平仓超时被明确记录, so that 异常安全路径与正常路径同样可审计。
38. As a SimNow 操作者, I want 多合约报告中的状态、委托和成交严格按合约隔离, so that 一个合约的动作不会错误归属另一个合约。
39. As a SimNow 操作者, I want 报告顶部看到每个合约的终态、轮数、停止原因、失败原因和最终净仓, so that 我能先掌握整个 run 的结果。
40. As a SimNow 操作者, I want 报告顶部看到起始资金、结束资金和资金差净盈亏, so that 真实结果与账户变化一致。
41. As a SimNow 操作者, I want 看到推算手续费及其口径说明, so that 理论毛盈亏与真实资金差之间的差额可以解释。
42. As a SimNow 操作者, I want 每个完成轮次看到按成交价、数量和合约乘数计算的毛盈亏, so that 我能比较各轮表现。
43. As a SimNow 操作者, I want 单笔委托不显示无法可靠归因的净盈亏, so that 页面不会提供虚假的精确数字。
44. As a SimNow 操作者, I want 无动作 Tick 和 Clock 不出现在解释时间线中, so that 数千条无变化事件不会淹没关键流程。
45. As a SimNow 操作者, I want 原始无动作事件仍保留在审计日志, so that 减少 HTML 噪音不会删除底层事实。
46. As a SimNow 操作者, I want 成功终态和失败终态都能生成报告, so that 安全失败也可以被复盘。
47. As a SimNow 操作者, I want 活动中 run 被拒绝生成, so that 未完成的委托、仓位和资金不会被误认为最终结果。
48. As a SimNow 操作者, I want 无完整摘要的崩溃 run 被拒绝生成, so that 不完整数据不会伪装成完整报告。
49. As a SimNow 操作者, I want 没有结构化因果轨迹的旧 run 被明确拒绝, so that 报告不会根据当前代码重建历史原因。
50. As a SimNow 操作者, I want 命令清楚指出拒绝原因, so that 我能区分旧格式、活动中运行和缺失文件。
51. As a SimNow 操作者, I want HTML 是自包含单文件且没有外部依赖, so that 离线打开、复制和归档都不受网络影响。
52. As a SimNow 操作者, I want 报告生成到独立报告目录而不写回审计目录, so that 原始证据与派生视图保持分离。
53. As a SimNow 操作者, I want 可选在生成后自动打开浏览器, so that 日常查看少一步操作。
54. As a SimNow 操作者, I want 现有交易日报告命令继续工作, so that 新的单 run 报告不会破坏已有复盘方式。
55. As a SimNow 操作者, I want 报告永远不在策略运行结束时自动生成, so that 报告失败不会影响下单或收口。
56. As a 安全负责人, I want 新增因果轨迹继续通过凭证字段检查, so that 账号、密码、前置地址和授权信息不会进入报告或日志。
57. As a 开发者, I want 原因代码和数值事实落盘而中文文案留在报告层, so that 调整展示文案不改变审计协议。
58. As a 开发者, I want 历史解释不随状态机代码演进而变化, so that 同一 run 在未来重新生成时仍得到相同因果结论。
59. As a 开发者, I want 一个事件允许携带多条因果轨迹, so that 单个回调连续触发多个有意义步骤时不会丢失中间原因。
60. As a 开发者, I want 报告器只做校验、聚合和渲染, so that 交易决策逻辑不会在第二处被复制。

## Implementation Decisions

- **事实源边界**：结构化审计因果轨迹是运行委托成交报告解释决策原因的唯一事实源。报告器不得重放状态机、读取当前策略代码推断历史原因，或根据最终结果猜测中间过程。
- **根因修复位置**：状态机处理事件时拥有锚点、最新行情、替换原因、计时起点、净仓与安全参数，因此必须在该公共决策边界产出轨迹；适配层和审计写入器只负责传递、凭证校验与序列化，不重新计算策略原因。
- **审计格式版本**：新 run 必须带显式审计格式版本，使报告在读取任何业务事件前即可区分支持格式与旧格式。版本属于审计协议，不属于策略参数或策略哈希语义。
- **轨迹形态**：每条事件记录可附带零到多条因果轨迹。每条轨迹使用稳定原因代码，并按需要包含受影响的 client identities、行情输入、状态输入、计时输入、计算操作数、判定结果与产生的动作；不落盘本地化中文说明。
- **轨迹产生范围**：会话状态变化、下单/撤单/查询/告警动作、委托状态变化和成交必须有足够的因果事实。没有产生状态、动作、委托或成交变化的 Tick/Clock 继续保留原始事件，但不附加解释轨迹。
- **报价事实**：报价轨迹记录当时最新价、买一、卖一、锚点价格、最小变动价位、W、D、距离 tick 数、买价、卖价和受影响的双边报价 identities，使 HTML 只做算式排版。
- **盘口保护事实**：盘口保护轨迹记录买卖价差、向上取整后的 spread ticks、W+D、保护倍数、严格比较两侧操作数及布尔结果，明确区分保护暂停与重定锚。
- **重定锚事实**：重定锚轨迹记录旧锚点、当前价格及 tick、W 边界、S 步长、越界开始时间、实际持续时间、确认阈值、新锚点、被撤报价和后续替代关系。
- **替代关系**：撤单开始时记录被替代的双边报价 identities；稳定行情重新满足并提交下一组报价时，记录其前驱 identities 与原始替代原因。每笔逻辑委托仍保持独立，报告通过关联关系展示完整链路。
- **成交与收口事实**：首次成交、窗口内对侧成交、窗口超时、净仓计算、受限 FAK 定价、平仓终态、剩余委托撤销、关联查仓、轮次完成或失败都记录直接输入与原因代码。成交事实继续以 CTP 委托/成交回报为权威。
- **状态原因完整性**：启动、稳定行情资格、报价、替换、价差窗口、平仓、撤单收口、对账、继续下一轮、正常结束和失败的每次有意义状态变化都必须能由同条事件的轨迹直接解释。
- **不改变策略行为**：新增轨迹只能观察并复制状态机当次已经使用的值，不得增加行情查询、账户查询、委托、撤单、计时器或状态转换，也不得改变动作顺序和安全限制。
- **运行报告输入**：单 run 模式接受 run 级审计目录，而不是单个合约事件文件或审计根目录。它自动发现该 run 的全部合约子目录和运行级资金、策略与摘要文件。
- **输入门槛**：只接受具有受支持审计格式版本、完整 run 摘要且所有合约已进入终态的 run。FINISHED 与 FAILED 都有效；旧格式、活动中和无摘要崩溃 run 以非零退出码拒绝，且不输出降级 HTML。
- **现有模式兼容**：单 run 模式扩展现有报告命令；现有按审计根目录与交易日生成报告的行为和参数保持兼容。
- **输出**：单 run 报告写入独立报告目录，文件名由 run identity 稳定派生；可选生成后打开。审计目录保持只含事实，不写入派生 HTML。
- **页面结构**：自包含单文件 HTML，无外部 CSS、JavaScript、字体或 CDN。页面依次展示 run 总览、运行参数与策略哈希、资金结果，然后按合约展示审计品种身份、运行因果时间线、轮次结果和逻辑委托表。
- **委托主表**：每个合约一张完整委托表，按实际提交时间排序。每个 client identity 合并为一行，展示用途、方向、开平、类型、价格、数量、去重状态路径、成交量和终态；买卖报价与 FAK 平仓不拆表。
- **可展开详情**：使用浏览器原生折叠语义提供默认收起的详情，不引入交互框架。详情将原因代码和结构化数值翻译为中文流程，并链接相关成交、配对报价、前驱和后继委托。
- **运行因果时间线**：只展示无法归属单笔委托的合约级轨迹，如元数据门槛、零仓确认、稳定行情资格、轮次对账、终止与失败；委托专属轨迹只在委托详情展示，避免重复。
- **审计品种身份**：展示品种代码、准确合约、交易所、乘数和最小变动价位。不得维护中文品种映射，也不得用报告生成时的当前合约信息覆盖历史值。
- **参数边界**：运行参数来自 run 保留的完整生效策略与哈希；委托参数来自实际提交动作。两者独立展示，避免把配置意图当作已发送委托。
- **逻辑委托合并**：同一 client identity 的重复委托回报合并为一个生命周期；状态路径按首次出现顺序去重，终态以 CTP 回报为准；多个 TradeEvent 保持可逐笔查看并提供数量/加权价汇总。
- **盈亏口径**：沿用既有决策。完成轮次展示按成交价、数量、方向、合约乘数和最小变动价位计算的毛盈亏；run 汇总展示资金差净盈亏及推算手续费；不向单笔委托或并发合约分配不可靠的净盈亏。
- **时间口径**：交易所委托/成交时间用于用户可读时刻；审计单调钟用于事件排序和持续时间计算。页面明确两者用途，避免把交易所秒级时间用于毫秒间隔。
- **安全边界**：结构化轨迹和最终 HTML 都必须继续通过既有凭证字段禁止规则；不得包含账号、用户名、密码、认证字段、产品信息或前置地址。
- **文档约束**：使用领域词汇“逻辑委托”“运行参数”“委托参数”“审计品种身份”“审计因果轨迹”“运行因果时间线”和“运行委托成交报告”，并遵循 ADR 0007 的不推导边界。

## Testing Decisions

- **主要高层接缝**：优先使用一个端到端临时目录接缝——以假 CTP/vn.py 事件驱动现有适配器和状态机，经真实审计写入器产出完整终态 run，再调用报告命令，最后只断言落盘审计协议、退出结果和 HTML 可见内容。这个接缝同时证明“决策值没有在写入边界丢失”和“报告无需重放即可展示”。
- **外部行为优先**：测试原因代码、数值事实、动作数量、终态、命令退出码和用户可见 HTML；不直接断言新增私有字段或辅助函数调用。
- **状态机先例**：沿用直接构造 Contract、Tick、Clock、Order、Trade 和 PositionQueryComplete 事件推进会话的模式，构造确定性的报价、盘口暂停、重定锚、成交和收口场景。
- **适配器先例**：沿用假主引擎与简单 vn.py 事件对象驱动适配器的模式，验证新增审计轨迹不会改变发单、撤单、查询数量与顺序。
- **审计先例**：沿用临时目录读取 JSONL/JSON 产物并验证凭证过滤的模式，断言格式版本、零到多条轨迹、稳定原因代码和结构化值真实落盘。
- **报告先例**：沿用“合成或真实临时审计目录进、HTML 文件出”的命令级模式，断言页面标题、关键中文流程、表格行、详情、链接关系和盈亏数字。
- **首次报价必测**：给定已知 tick、pricetick、W 和 D，审计必须保存锚点与买卖计算操作数；HTML 必须展示与实际 submit actions 相同的价格。
- **盘口保护必测**：覆盖严格不等式边界相等时失败，验证日志明确记录 market pause、spread ticks、两侧操作数和 false 结果，且报告不把它解释为重定锚。
- **重定锚必测**：覆盖首次越界不撤单、确认时长达到后撤单、S 步长移动锚点、撤单终态后重新资格与替代委托链接。
- **委托合并必测**：同一 client identity 多次 SUBMITTING/NOTTRADED 回报只生成一个主表行，状态路径去重且终态正确。
- **成交必测**：覆盖单笔成交、部分成交、多笔成交、重复成交回报去重、成交与委托关联，以及成交回报晚于委托回报的顺序。
- **价差窗口必测**：覆盖窗口内对侧成交的价差完成分支与窗口超时的 FAK 分支，断言对应原因、计时输入、净仓和后续动作在日志与 HTML 一致。
- **FAK 必测**：覆盖多次 FAK 尝试、不利 tick 上限、拒单、超时和成交后撤对侧，断言报告展示实际使用的可执行价与安全上限。
- **对账必测**：覆盖关联 request identity、净仓归零继续下一轮、非零仓进入平仓、查询错误失败和最终轮数上限结束。
- **异常必测**：覆盖操作员中断、撤单超时、迟到开仓成交、迟到平仓成交和失败终态，确保每个有意义状态变化都有直接原因轨迹。
- **多合约必测**：一个 run 至少包含两个合约，断言报告自动发现全部合约、参数和事件不串线、运行时间线和委托表分别渲染。
- **盈亏必测**：复用既有毛盈亏、资金差与推算手续费场景；断言 run 级净盈亏不被分摊到单笔委托或并发合约。
- **输入拒绝必测**：旧格式 run、无 run 摘要、非终态摘要、缺合约事件、格式版本不支持分别以明确错误和非零退出码拒绝，且不留下看似成功的 HTML。
- **终态必测**：FINISHED 和 FAILED 的完整新格式 run 都能生成，失败原因和最终净仓在页面醒目可见。
- **噪音边界必测**：无状态/动作/委托/成交变化的 Tick/Clock 仍写入事件日志但不带因果轨迹，也不进入 HTML 时间线。
- **命令兼容必测**：现有交易日报告参数和输出继续通过原有测试；新 run 模式的输出命名、报告目录和可选打开行为单独覆盖。
- **安全必测**：把禁止凭证键放入轨迹任意嵌套层都必须在审计边界拒绝；生成 HTML 不得包含账户 identity 或连接凭证。
- **不做真实交易测试**：自动验证不得连接 SimNow、不得发送真实委托。实现完成后使用新格式本地样例生成 HTML；只有未来真实终态 run 才能产生真实运行报告。

## Out of Scope

- 为没有结构化审计因果轨迹的历史 run 生成基础、降级或推导报告。
- 在报告器中复制或重放报价、重定锚、盘口保护、价差窗口、FAK 或状态机规则。
- 为活动中 run 生成实时快照报告。
- 为无完整 run 摘要的崩溃运行生成部分报告。
- 在策略结束时自动触发报告生成，或让报告失败影响实时运行终态。
- 替换或删除现有按交易日聚合的成交明细报告。
- 按交易日、跨 run 或跨账户聚合新的因果报告。
- 展示或维护中文品种名称映射，或接入外部合约信息服务。
- 精确逐笔手续费、逐笔净盈亏、逐合约资金差归因或结算单对账。
- 修改报价公式、盘口保护、重定锚、价差窗口、受限 FAK、查仓或安全终态语义。
- 为每一条无动作 Tick/Clock 生成“为什么没做事”的说明。
- 引入前端框架、外部 JavaScript/CSS、服务端、数据库、搜索索引或分页系统。
- K 线、价格曲线、资金曲线、统计图表或交互式回放。
- 在审计或报告中保存账号、用户名、密码、认证信息、产品信息或前置地址。
- 通过连接 SimNow 或发送委托来完成自动化验收。

## Further Notes

- 最初用于分析的 `20260817T150447.383107Z-e5aa7040c9` run 属于旧审计格式，只能作为需求与测试场景的证据，按本规格不得生成新的运行委托成交报告。
- 该旧 run 的 3,777 条事件中有 155 笔逻辑委托、746 条委托状态回报和 10 条成交回报，说明按 client identity 合并与过滤无动作事件是必要的；这些数字不是新格式协议的一部分。
- 对旧 run 的源码对照显示，65 次从报价进入替换中有 57 次由盘口保护失败触发、8 次由重定锚触发；新格式必须把这种区别在发生时直接落盘，而不是让报告重复这次人工分析。
- 新格式第一个真实报告只能来自功能上线后新产生且正常收尾的 SimNow run。实现验证使用本地确定性样例，不以真实下单作为完成条件。
- 报告是审计事实的一种派生视图，可以在不改变审计内容的前提下反复生成和调整样式；审计日志仍是唯一事实源。
- ADR 0007 固定了“运行时记录因果、离线报告只消费、旧日志拒绝”的边界；未来若要支持旧日志迁移或活动中快照，应另立规格并显式改变该决定。
