# 01 — 价差窗口收口（spec）

**What to build:** 首次成交不再立即撤销对侧报价：对侧挂满 `closing_wait_seconds`（默认 1 秒，0 为无窗口），窗口内对侧成交则价差落袋直接对账结束，超时则受限 FAK 平掉净仓后再撤对侧；两条分支都以"全部委托终态 + 对账净仓为零"收尾。

**Blocked by:** 无（取代原"立即撤单收口"语义，见 ADR 0006）

**Status:** ready-for-agent

## Problem Statement

现行收口语义（任一首次成交立即撤销全部剩余委托、对账、平仓）是报撤联调测试器的安全设计，策略永远拿不到网格价差的自然完成——对侧报价在成交瞬间就被撤掉，一笔本可双边落袋的价差总是被 FAK 平仓打断并支付额外手续费。操作者需要给对侧一个成交窗口，观察并验证网格的真实盈利路径。

## Solution

把收口从"立即撤单收口"改为"价差窗口收口"（ADR 0006）：首次成交后对侧报价继续挂 `closing_wait_seconds`；窗口内对侧成交 → 本轮价差完成、不平仓；窗口超时 → 受限 FAK 平掉净仓 → 平仓终态后撤对侧。两条分支统一以"全部委托终态 → 关联对账查仓 → 净仓为零"结束，保持每轮无遗留委托、无遗留仓位的安全基线。窗口时长为策略配置项，进入策略哈希身份。

## User Stories

1. As a SimNow 操作者, I want 首次成交后对侧报价继续挂满配置的窗口时长, so that 网格价差有机会自然完成而不是被立即撤单打断。
2. As a SimNow 操作者, I want 窗口内对侧成交时本轮直接以价差完成结束、不做任何平仓, so that 双边挂单的利润完整落袋且省掉平仓手续费。
3. As a SimNow 操作者, I want 窗口超时后按当时净仓走受限 FAK 平仓, so that 敞口不会超过窗口加平仓时长。
4. As a SimNow 操作者, I want FAK 平仓终态后再撤对侧单, so that 对侧在平仓完成前仍有成交机会，且一轮结束时不遗留任何委托。
5. As a SimNow 操作者, I want 两条分支都以"全部委托终态 + 对账查仓净仓为零"收尾, so that 每轮结束的状态被 CTP 事实确认而不是推断。
6. As a SimNow 操作者, I want 窗口时长做成 `closing_wait_seconds` 配置项（默认 1、允许 0）, so that 可以对照实验不同窗口的价差完成率而不用改代码。
7. As a SimNow 操作者, I want 配置变更反映在 canonical JSON 与策略哈希里, so that 每次审计都能确认当轮使用的窗口时长。
8. As a SimNow 操作者, I want 窗口内对侧一成交就立即结束窗口（不等满时长）, so that 轮次周转最快。
9. As a SimNow 操作者, I want 窗口期间操作者中断仍走人工结束收口（撤全部、查仓、有仓则 FAK）, so that 中断安全与现状一致。
10. As a SimNow 操作者, I want 窗口或平仓期间的迟到开仓成交由既有迟到成交触发兜底, so that 任何时刻的净仓变化都会触发新一轮收口而不是被忽略。
11. As a SimNow 操作者, I want 部分成交按净仓算术处理、以对账查仓为权威, so that 多手数或部分成交场景不会算错平仓量。
12. As a SimNow 操作者, I want 报告的每轮明细新增"结束方式"列（价差完成 / FAK 平仓）, so that 直接观察窗口的价差完成率。
13. As a SimNow 操作者, I want 平仓相关的既有规则（受限 FAK 的 3 秒/10 tick 重价、撤单终态上限、收盘停止、往返轮数上限）原样保留, so that 只有收口顺序变化、安全边界不放宽。
14. As a 开发者, I want 状态机改造后既有安全不变量（不遗留委托、不带仓重挂、失败显式残留）全部有测试覆盖, so that 重构没有静默放宽任何边界。

## Implementation Decisions

- **状态机重排**：首次成交进入等待窗口（对侧单保持活动），不再触发全线撤单；窗口计时由时钟事件推进。窗口结束（对侧成交或超时）后才进入撤单/平仓/对账序列。
- **对账门槛调整**：关联查仓的发起条件从"无任何活动委托"调整为两条检查点——价差完成分支的全部委托终态后，与 FAK 平仓加撤对侧全部终态后。
- **配置**：`closing_wait_seconds` 非负整数/零，默认 1；纳入 canonical JSON 与策略哈希；0 表示无窗口（成交即平仓，但仍先撤对侧？否——0 与超时路径一致：直接按净仓 FAK、平仓终态后撤对侧）。
- **报告**：轮次记录增加结束方式字段（价差完成 / FAK 平仓），渲染为新列；按 ADR 0004 仍由审计离线生成。
- **文档**：运行时文档的收口章节与 PRD 按新语义重写；词汇表与 ADR 0006 已先行落地。
- **沿用不变**：受限 FAK 收口、撤单终态上限、收盘停止、往返轮数上限、迟到成交触发、人工结束收口、零仓启动门槛、报撤限流。

## Testing Decisions

- 只测外部行为：沿用会话测试直接构造事件的接缝，断言动作序列与终态，不断言内部状态字段。
- 必测路径：窗口超时主路径（不撤对侧 → FAK → 撤对侧 → 查仓 → 净仓 0 完成）；窗口内对侧成交路径（不平仓、无 FAK 动作、查仓净仓 0 完成）；`closing_wait_seconds=0`；窗口内中断；窗口/平仓期间迟到开仓成交；部分成交净仓算术；配置校验（默认值、非法值拒绝、哈希变化）。
- 既有"首成交立即撤单"的测试用例按新语义改写，安全不变量类用例（不带仓重挂、无遗留委托结束）保留并适配。
- 报告"结束方式"列沿用"合成审计目录进 → HTML 出"接缝。
- 先例：`tests/test_session.py`（事件驱动状态机）、`tests/test_strategy_config.py`（配置校验与哈希）、`tests/test_report.py`（报告接缝）。

## Out of Scope

- 对侧单跨轮续挂（平仓后继续保留到下一轮）——已拒绝（破坏无遗留委托基线）。
- 窗口时长的动态调整（按行情自适应）。
- 窗口内行情失效的特别处理（FAK 可执行价规则已覆盖）。
- 逐轮资金差归因、手续费精确值（维持 ADR 0005 口径）。

## Further Notes

- 敞口存续时间从亚秒延长到"窗口 + 平仓时长"，这是本设计的代价，操作者应以 `closing_wait_seconds` 控制上限。
- 对侧在 FAK 执行期间成交（迟到成交）会使净仓翻向，既有迟到成交触发机制会再开一轮收口，属预期行为。
- 报告的"成交→平仓"间隔列在价差完成分支将无平仓成交可计，应显示"—"或该分支的等价语义。
