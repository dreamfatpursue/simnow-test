# 0002. 多合约运行采用每合约独立会话

**状态：已采纳**

## 背景

实时网格会话原为单合约设计：锚点、行情、挂单、净持仓均为单实例标量，CTP 适配层的订阅与回报过滤硬编码单一目标合约。现需在同一 SimNow 运行中对多个合约品种同时挂单。备选方案是把会话内部状态改为按合约的容器，或为每个合约实例化一个既有的单合约会话。

## 决策

每个目标合约实例化一个独立的单合约实时网格会话；CTP 适配层持有合约到会话的映射，按事件携带的合约路由行情、委托、成交与合约元数据，并订阅全部目标合约。策略配置采用顶层公共网格参数加每合约条目（合约、交易所、每侧手数）的结构；报撤限额与首次成交收口按会话独立执行；持仓查询发起一次账户级查询，由适配层按合约拆分广播。任一合约非零持仓则整个运行拒绝启动。运行在全部会话到达终态后结束；操作员中断广播至全部会话。

## 考虑过的备选方案

- 单会话内维护按合约的状态容器：改动面大且引入状态串扰风险，仅在需要跨合约联动（共享限额、互相对冲）时才值得。
- 全局共享报撤限额池：会使某合约的必要安全撤单被其他合约耗尽限额挤掉，违背安全撤单不可绕过的语义。
- 任一合约收口即全局停机：合约数量增多后"一个成交全停"使多合约失去意义，且引入跨会话触发链路。

## 后果

一个会话的收口失败不会拖停其他会话，各合约各自兜底。账户级总报撤频率随合约数线性增长，每会话限额不控制总量。跨会话的委托号在适配层按合约隔离，避免撞号。
